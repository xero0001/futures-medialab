# 운영 콘솔

`apps/admin`은 같은 모노레포의 별도 Next.js 앱입니다. `apps/platform`과 PostgreSQL/Prisma 모델을 공유하고 별도 Vercel 프로젝트로 배포합니다.

## 접근 제어

- 공개 회원가입, 비밀번호 재설정, 계정 수정 API는 제공하지 않습니다.
- 활성 `PLATFORM` 조직의 `OWNER` 또는 `ADMIN` 멤버만 접근 가능합니다. 일반 브랜드·에이전시의 조직 관리자 역할과 다릅니다.
- 모든 관리 API와 서버 페이지가 권한을 DB에서 재확인합니다. 변경 트랜잭션에서는 세션 유효성도 다시 확인합니다.
- 관리자 쿠키 이름은 `futures-medialab-admin`으로 분리합니다. 이 프로젝트 전용 `BETTER_AUTH_SECRET`과 정확한 `BETTER_AUTH_URL`을 설정하세요. 플랫폼의 인증 secret을 재사용하지 마세요.
- 최초 관리자는 운영자가 별도 안전한 절차로 생성하거나 기존 사용자에게 `PLATFORM` 멤버십을 부여해야 합니다. 자동 권한 상승 기능은 없습니다.
- 이메일 인증 상태를 임의로 변경하지 않습니다. 이메일 OTP·MFA는 아직 연결되어 있지 않습니다. 실서비스 운영 확대 전에 추가해야 합니다.

## 로그인 화면

로그인은 서비스 인증 화면과 같은 Montage 4.1.5 디자인 시스템을 사용합니다. Pretendard, 원티드 블루, 48px 입력창·버튼과 중앙 카드형 반응형 레이아웃을 적용하고, 로그인과 내부 화면이 공통 `AdminProvider`를 사용하고 로그인 스타일은 CSS module로 분리합니다. 관리자 권한 검사와 권한 없는 계정의 세션 종료는 기존 인증 흐름을 유지합니다.

## 내부 화면

헤더·모바일 메뉴·그레이톤 사이드바는 `AdminShell`, 관리 버튼은 `AdminButton`으로 공통화했습니다. Montage TopNavigation·ListCell·Button과 Pretendard, 원티드 블루를 사용하며 사용자·조직·캠페인·요청함·변경 이력에 같은 스타일을 적용합니다. 모바일 메뉴는 Escape로 닫기, 초점 이동·복귀와 키보드 순환을 지원합니다. 표는 좁은 화면에서 내부 가로 스크롤로 확인합니다.

## 기능

- 사용자 조회, 소속 조직·역할·이메일 인증 상태 확인, 일반 사용자 세션 종료
- 회사 정보와 비공개 사업자 증빙 검토, 조직 승인·보완 요청·이용 정지
- 캠페인 검토, 보완 요청 (`REVIEW → DRAFT`), 경로별 운영 승인과 진행 전환
- 오픈 캠페인: 공개 승인 (`REVIEW → RECRUITING`), 모집 마감 (`RECRUITING → IN_PROGRESS`)
- 맞춤 제안: 승인·소싱 시작 (`REVIEW → RECRUITING`), 소싱 완료·진행 (`RECRUITING → IN_PROGRESS`). 같은 DB 상태값을 쓰되 화면에는 `소싱 중`으로 표시
- 캠페인별 공급사 신청 및 원제안 조회. 브랜드가 검토하는 공식 제안 발행·승인 모델과는 별개
- 공식 제안서 비공개 초안 작성·저장, 브랜드 공개 미리보기, 명시적 발행, 새 버전 작성·재발행
- 발행된 제안의 항목별 브랜드 승인·수정 요청 이력 조회. 전체 항목 승인 시 캠페인 진행 단계 전환
- 승인된 제안의 제작 항목 준비·공급 파트너 배정, 에이전시 제출본 검토·보완 요청
- 원문과 분리한 브랜드 공개본 미리보기·공개, 브랜드 검수 승인·수정 요청과 버전 이력 확인
- 주요 변경 및 증빙 다운로드 감사 기록

운영 승인은 활성 브랜드, 플랫폼·요약 및 양수 예산이 필요합니다. 오픈 캠페인은 미래 신청 마감일, 맞춤 제안은 미래 희망 게시일을 추가로 검증합니다. 맞춤 제안에 모집 마감일을 강제하지 않으며, 과거 모집 마감일이 남아 있어도 에이전시 목록·직접 지원 API는 `OPEN_BIDDING` 유형만 허용합니다. 맞춤 제안의 48시간 예정 시각은 브랜드의 접수 완료 기준으로 기록되고, 운영자의 소싱 승인만으로 공식 제안이 자동 발행되지는 않습니다.

브랜드의 공급사 원신청 조회·직접 후보 지정·선정·거절 API는 404로 폐기했습니다. 공식 제안서는 캠페인 상세의 별도 패널에서 작성합니다. 해당 캠페인의 내부 검토 후보를 불러오거나 공개용 인물 정보를 직접 입력할 수 있습니다. 공급가와 내부 메모는 별도 필드에 보관하며 브랜드 공개 미리보기와 브랜드 API에서는 제외합니다. 발행본은 수정하지 않고 새 버전을 작성합니다. 발행과 브랜드 결정은 연결된 요청함에도 기록됩니다. `GET/POST /api/admin/proposals`는 별도 관리자 세션·활성 PLATFORM 권한·동일 출처·revision·재시도 키를 검증합니다.

제작·검수는 `GET/POST /api/admin/production`을 사용합니다. 에이전시 제출 원문은 내부에서 검수한 뒤 별도 공개 제목·링크·설명을 작성해 브랜드에 전달합니다. 수정본도 매번 검수를 거치며, 공개된 버전은 덮어쓰지 않습니다. 공식 제안 캠페인의 기존 콘텐츠 승인 API는 차단하고 새 제작·검수 패널로 안내합니다.

콘텐츠 승인 이후에는 `GET/POST /api/admin/reporting`으로 게시 링크·집계 시각·8개 성과 지표·참고 자료를 검토합니다. 원문과 브랜드 공개본을 분리하고, 보완 요청 또는 미리보기 확인 후 공개합니다. 추가 보고도 새 버전으로 검수하며 브랜드에는 마지막 공개본을 유지합니다. [이환 게시·성과 시연](../../docs/design/nte-reporting-demo.md)을 참고하세요.

`GET/POST /api/admin/settlement`는 최신 콘텐츠·성과·금액 확인 후 캠페인 완료와 브랜드 청구·에이전시 지급을 별도로 처리합니다. 각 문서는 비공개 초안 검토 후 명시적으로 발행합니다. 청구액은 확정 단가×수량, 지급액은 항목 총공급가의 합계이며 공급가에 수량을 다시 곱하지 않습니다. 미입금 브랜드 청구서의 제목·안내·기한·원본 링크를 정정하면 새 문서 버전을 발행합니다. 입금·지급 확인 시 외부 처리 금액·통화·시각·참조를 검증합니다. [이환 완료·정산 시연](../../docs/design/nte-settlement-demo.md)을 참고하세요. 문서·공유 탭에서 제안·성과·청구·지급·요청 첨부를 공개 범위별로 통합 조회합니다. 일반 문서 생성·계약 서명·송금·SNS 게시는 실행하지 않습니다.

조직 정보 보완 요청은 기존 프로필·문서를 보관하고 제출 완료 표시만 해제하여 재입력을 허용합니다. 플랫폼 운영 조직의 정지·권한 변경은 이 콘솔에서 지원하지 않습니다.

사용자·조직 목록은 최근 200개, 감사 기록은 100개, 캠페인별 신청은 100개까지 표시합니다. 캠페인 목록은 전체 데이터를 서버에서 검색하고 25건씩 조회합니다. 운영 업무 목록은 전체 집계와 30건 단위 서버 페이지 이동을 제공합니다.

## 환경 변수

- `DATABASE_URL` (기존 플랫폼과 동일 DB, 연결 풀 사용)
- `BETTER_AUTH_URL` (관리자 앱의 정확한 origin)
- `BETTER_AUTH_SECRET` (관리자 앱 전용, 최소 32자)
- `BLOB_READ_WRITE_TOKEN` (기존 비공개 사업자 증빙 저장소, 다운로드를 위해 필요)

증빙은 로그인·관리자 권한 검증 후 서버에서 읽고 첨부파일로 전달합니다. Blob URL·키·파일 경로를 클라이언트에 노출하지 않습니다.

## 2026년 11월 운영 화면 정리

운영 홈은 접수·회신, 공식 제안, 모집 마감, 제작·성과 검토, 완료·발행, 브랜드 미입금과 파트너 미지급 업무를 기한순으로 모읍니다. 담당자 미배정·내 업무·기한 초과·48시간 이내와 종류별 필터를 제공합니다. 최초 제작 항목 준비, 수행 조직 배정, 성과 항목 준비와 청구·지급 초안 발행도 목록에 포함합니다. 과거 제안의 제작·성과 항목은 현재 업무에서 제외하며 완료 캠페인의 미입금·미지급은 유지합니다.

캠페인은 맞춤 의뢰·오픈 모집으로 구분해 검색합니다. 상세는 진행 개요, 후보·소싱, 공식 제안, 제작·검수, 게시·성과, 문서·공유, 청구·지급, 기존 운영 기록 탭으로 나눕니다. `/?tab=campaigns&campaign=<id>&section=documents`처럼 캠페인과 탭을 주소에 보관하며 요청은 `/?tab=requests&request=<id>`로 연결합니다. 새로고침·뒤로 가기에서도 선택을 유지하고 미저장 편집은 이동 전에 확인합니다.

후보·소싱에서는 기존 공급 신청을 후보·확정·미선정으로 검토합니다. 현재 스키마의 신청 단위 상태를 사용하고 공식 제안에서는 개별 인물을 선택합니다. 활성 공급 조직과 크리에이터, 동시 수정, 이미 발행된 제안·수행 기록을 검사하고 사유를 감사 이력에 남깁니다. 후보 지정 자체는 브랜드 공개가 아닙니다.

제안 초안 발행 시 공급가 누락을 안내하고, 발행 후에도 완료·청구·지급 기록을 생성하기 전에는 내부 공급가를 별도 보완할 수 있습니다. 공개 버전과 항목·승인·제작 이력은 유지하며 내부 변경 사유와 revision을 기록합니다. 캠페인 완료 이후에는 보완을 차단합니다.

접수 의뢰의 `waitingFor`는 제안 결정·자료 보완·일반 회신을 구분합니다. 공개 안내와 회신/보완 요청은 별도 동작이며 회신 요청은 메시지·상태·기한을 함께 저장합니다. 브랜드의 질문과 재검토는 `operatorReplyPending`으로 운영 업무에 반영합니다. 최초 제안 약속 시각은 보존하고 보완 중 현재 처리 기한은 비우며 재접수 시 새 운영 기한을 기록합니다. 브랜드 질문이 제안 승인 또는 캠페인 재접수를 대신하지 않습니다.

문서·공유 탭은 비공개 초안·브랜드 공개·파트너 공개를 구분해 버전·수신 조직·공개 시각·내용을 확인하고 기존 발행/공유 화면으로 이동합니다. 첨부는 기존 인증 다운로드 경로를 사용합니다. 종류별 최대 100건의 표시 한도를 안내하고 미전송·폐기 첨부는 제외합니다. 정정 발행된 청구서도 같은 탭에서 원본과 버전별 내용을 확인합니다.

새 데이터 경로는 `GET /api/admin/operations`, `GET /api/admin/campaigns`, `GET /api/admin/campaign-documents`, `GET/POST /api/admin/sourcing`입니다. 기존 활성 PLATFORM 관리자 권한·세션 재검사·동일 출처·감사 이력 원칙을 유지합니다. 이번 정리는 기존 모델과 JSON 메타데이터를 사용하며 DB 마이그레이션을 요구하지 않습니다.

## 대리 접수와 내부 크리에이터 관리

운영자가 `대리 접수`에서 활성 브랜드와 그 조직의 소유자 또는 관리자를 실제 의뢰자로 선택하고 브리프를 등록합니다. 구매자 대행사 의뢰에는 최종 광고주를 입력합니다. `맞춤 의뢰`는 접수 시각부터 48시간의 최초 제안 기한을, `오픈 모집`은 입력한 모집 마감을 사용합니다. 브랜드는 일반 의뢰와 같은 캠페인 및 요청함에서 확인합니다. 캠페인 개요에는 실제 의뢰자·접수 운영자·접수 경로를 표시하고 대리 접수 사유는 관리자 변경 이력에 기록합니다.

`내부 크리에이터 DB`에서 자사·파트너·무소속 인물의 채널, 가용 일정, 경쟁 제한과 담당자를 관리합니다. 파트너 인물은 승인된 에이전시 및 해당 로스터에 연결할 수 있습니다. 단가표는 버전별로 보관하며 가격과 가용성을 마지막으로 확인한 날짜가 90일 이상 지난 인물을 찾을 수 있습니다. 공식 제안 초안에서 인물·채널·가격을 선택하고 브랜드 공개 내용을 검토한 뒤 발행합니다. 공급가·내부 기록은 운영 화면에서 관리합니다.

`청구·지급`에서 발행한 미입금 청구서의 안내를 정정하려면 새 제목·기한·문서 링크 등 변경 내용과 브랜드에 공개할 사유를 입력합니다. 같은 청구 건에 새 버전을 발행하므로 승인 금액·통화·항목과 미수 건수는 유지됩니다. 브랜드는 청구 화면과 자료실에서 정정본과 이전 발행본을 볼 수 있습니다. 입금 완료 후에는 청구서 이력을 조회합니다.

배포 시 애플리케이션 교체 전에 대상 DB에서 `pnpm --filter @futures-medialab/database db:migrate:deploy`를 실행합니다. `20261107010000_internal_creator_catalog`는 운영 전용 인물·단가표와 제안의 내부 출처를 추가합니다. `20261107030000_brand_invoice_versions`는 기존 발행·입금 완료 청구서의 발행 정보를 v1으로 보존하며 초안은 최초 발행 시 v1을 생성합니다.
