# Futures MediaLab 브랜드 화면 기획과 유다오 비교

2026-11-01 · 제품 기획 기준 및 화면 검토안

브랜드는 캠페인 조건을 전달하고, 퓨처스가 확정한 제안과 제작물을 승인하며, 집행 결과를 확인한다. 퓨처스는 후보 조사·선정·파트너 소통·집행을 담당한다. 브랜드 화면은 이 업무를 하나의 캠페인 안에서 이어 주는 구조로 구성한다.

크리에이터의 전체 DB는 공개하지 않는다. **프리뷰는 익명 구성으로 제공하고, 운영팀이 공식 제안서를 발송한 뒤 해당 캠페인에 제안된 크리에이터만 공개한다.** 공개된 인물의 채널·제작물·성과는 캠페인 안에서 확인할 수 있지만, 연락처·소속 공급 파트너·공급가·마진은 계속 비공개다.

화면 검토안은 별도 `/brand-preview` 경로의 예시 데이터와 화면 내 상태로 동작하는 시안이다. 실제 운영 화면의 후속 구현 범위와 남은 기능은 문서 마지막의 **실제 연결 구현 현황**에 기록한다. 시안에서 제안·검수·성과 화면을 볼 수 있다는 사실이 해당 운영 기능의 구현 완료를 의미하지는 않는다.

## 역할과 정보 공개 범위

브랜드와 구매자 광고 대행사는 같은 구매자 화면을 사용한다. 구매자 대행사에는 최종 광고주·게임별 구분을 추가한다. 공급 MCN·에이전시는 오퍼·신청·제작·지급을 담당하는 별도 역할이다. 화면의 “에이전시”라는 이름 하나로 구매자와 공급자의 권한을 합치지 않는다.

프리뷰에서 이름만 CSS로 감추지 않는다. 브랜드용 응답에는 이름·채널·사진·연락처·내부 실명 매핑을 포함하지 않고 티어·지표 범위·구성만 전달한다. 개인을 특정하기 쉬운 정확한 지표나 고유 설명도 프리뷰에 넣지 않는다.

공식 제안은 운영팀이 공개한 버전의 스냅샷을 제공한다. 크리에이터를 눌렀을 때 해당 제안의 상세가 열리며, 전체 DB 프로필이나 다른 캠페인의 이력으로 이동하지 않는다. 다른 조직·캠페인·미발송 버전은 URL을 알아도 조회할 수 없어야 한다. 첨부·다운로드·알림에도 같은 범위를 적용한다.

브랜드의 대안 요청은 후보 검색 기능으로 이어지지 않는다. 변경할 조건과 이유를 퓨처스에 보내고, 운영팀이 새 제안 버전을 발행한다. 거래 상대를 직접 고르는 흐름 대신 공식 제안의 건별 승인·반려·대안 요청을 제공한다.

## 브랜드의 기본 동선

```text
승인된 구매자 로그인
  → 홈
  → 새 요청: 브리프 → 익명 프리뷰 3안 → 경로 선택·제출
      ├─ 48시간 맞춤 제안 → 퓨처스 소싱·확정
      └─ 오픈 캠페인 → 운영팀 오퍼 작성·파트너 모집·선정
  → 공식 제안 수신: 캠페인에 제안된 인물·조건 공개
  → 건별 승인 또는 수정·대안 요청
  → 제작·검수·게시
  → 성과 확인·문서·청구
```

홈의 두 시작 카드와 마지막 단계의 경로 선택은 같은 값을 사용한다. 홈에서 고른 경로는 요청 폼의 초기 선택이며, 프리뷰를 확인한 뒤 최종 선택할 수 있다. 도중에 다른 경로로 전환해도 요청을 중복 생성하지 않는다.

사이드바는 **홈 / 캠페인 / 요청함 / 자료실 / 계정**으로 구성한다. 캠페인 상세에 **개요 / 제안·승인 / 제작·검수 / 성과 / 문서** 탭을 둔다. 문의는 해당 캠페인이나 제안·제작물에 연결해 요청함에서 모아 본다.

### 홈의 정보 우선순위

첫 화면에는 “내가 지금 처리할 일”과 “새 의뢰”를 함께 둔다. 48시간 맞춤 제안을 주 버튼으로, 오픈 캠페인을 보조 카드로 배치한다. 기존 거래처가 빠르게 의뢰를 맡길 수 있게 하되 두 경로를 모두 제공한다.

승인 대기 카드에서는 캠페인명·무엇을 확인해야 하는지·기한을 먼저 보여준다. 전체 크리에이터 수, 추천 인물, 인물 랭킹은 홈에 두지 않는다. 상태 배지에 색만 쓰지 않고 텍스트를 함께 표시한다.

### 새 요청과 익명 프리뷰

기획서의 브리프 항목을 입력 그룹으로 정리하되, 게임명과 장르를 구분하고 예산에는 통화를 반드시 표시한다. 구매자 대행사는 최종 광고주·게임을 선택한다. 비공개 게임/NDA와 추가 설명·자료를 보완 항목으로 둔다.

프리뷰는 실제 가용성과 확정 견적을 약속하지 않는다. 각 안에 인원·티어·매체·형식·수량·예산 범위·예상 도달 범위·선정 이유·일정과 권리 가정을 표시한다. 대표값만 제시해 확정 성과처럼 보이지 않게 한다. 기본 3안의 금액 상한은 입력 예산을 넘지 않게 하고, 증액이 필요한 안은 별도 선택으로 구분한다.

프리뷰의 실제 계산은 구조화 DB와 규칙으로 구현하며 LLM이 금액을 만들지 않는다. 이번 시안은 입력과 결과 비교의 화면 흐름을 검토하는 용도이며, 실제 가용성 확인이나 추천 엔진을 연결한 결과가 아니다.

### 공식 제안과 공개 시점

운영팀이 가용성·제작 조건·일정·판매가를 확인하고 공식 제안을 발송하면 해당 버전에 한해 인물 정보가 공개된다. 브랜드는 인물별 채널·관련 지표·제작 범위·건별 제안가를 보고 승인하거나 대안을 요청한다. 총액은 제안가의 합이며 공급가·수수료·마진으로 분해하지 않는다.

제안 상세에는 프리뷰와 달라진 점, 대체 후보가 포함된 경우 그 범위, 사용권·광고 표기 조건, 유효기간을 표시한다. 새 버전이 오면 변경된 인물·금액·일정을 구분하고, 과거 승인 기록은 당시 버전과 함께 유지한다. 이미 발송한 공식 제안이라는 이유로 같은 인물의 모든 DB 정보를 열어주지 않는다.

### 제작과 성과

제작물은 인물의 프로필보다 제출물·버전·마감일을 중심으로 보여준다. 브랜드가 검토할 영상 또는 문서와 퓨처스의 검수 코멘트를 함께 표시하고, 승인 이력은 제작물 버전에 연결한다.

성과 탭은 캠페인 합계와 실제 집행 항목을 함께 제공한다. 조회·클릭·참여·전환 지표는 확보 여부와 정의를 표시한다. 단축 링크는 캠페인과 제작물에 연결하며 PV·UV를 조회수나 구매 전환과 혼용하지 않는다. 댓글 분석은 해당 캠페인의 영상 선택에서 시작하고, 결과에는 집계 기간과 검토된 보고서 버전을 표시한다.

### 추가 확인 사항

- 크리에이터 검색 필터는 콘텐츠 유형·태그·채널 키워드, 채널 국가·팔로워·노출·노출 변동·최근 게시, 시청자 언어·국가·연령·성별로 나뉜다. 태그와 키워드에는 포함/제외 및 OR/AND가 있다. 검색을 새로 실행하지 않았고 체험 잔여 3/3 상태에서 확인했다.
- 즐겨찾기 상세의 열은 기본 정보·팔로워·평균 노출·태그·참여율·조회/팔로워 비율·최근 영상·평가·작업이다. 비어 있는 목록에서 실제 저장·평가 동작은 확인하지 않았다.
- 계정의 개인 정보에는 이름·직위·이메일·전화, 회사 정보에는 이름·업종·웹사이트·국가·규모·홍보 제품이 있다. 편집 상태와 빈 제품 행 추가 후 취소를 확인했다. 계정의 실제 개인·회사 값은 이 문서와 시안에 사용하지 않는다.
- 캠페인 메뉴의 문의 버튼은 브라우저 보안 정책에 의해 연결이 차단되어 목적 화면을 확인하지 못했다. 사이트 장애로 판단하거나 다른 경로로 우회하지 않았다.
- 앞선 분석 도구 조사에서 업그레이드 버튼은 `/en-US/upgrade`의 404 화면으로 연결되었다. 단축 링크·즐겨찾기에서는 별도의 업그레이드 팝업을 관찰했다.
- 현재 좁은 브라우저 너비에서 데이터 표와 일부 팝업이 가로로 잘렸다. Futures는 작은 화면에서 핵심 열을 우선하고, 상세는 별도 패널로 열어 읽기 폭을 확보한다.

### 가져올 패턴과 제외할 패턴

가져올 것은 목적별 입력폼, 필터를 의미별로 묶는 방식, 상태·처리 이력, 표의 상세 진입, 계정의 조회/편집 구분이다. 브랜드가 처리할 일이 있는 목록에서는 유다오의 빈 표보다 다음 행동을 안내하는 빈 화면을 제공한다.

브랜드에 제공하지 않을 것은 전체 크리에이터 디렉터리·유사 검색·동종 브랜드를 통한 인물 발굴·일반 즐겨찾기다. 분석·단축 링크는 캠페인의 맥락 안에서 사용한다. 유다오의 무료 체험·업그레이드 장치는 현재 Futures의 승인제 운영 모델에 그대로 가져오지 않는다.

## 데이터와 운영 구현 기준

- `Request`를 브랜드의 의뢰 단위로 삼고 경로·브리프·SLA·담당자·최종 광고주를 연결한다. 경로별로 서로 다른 캠페인을 중복 생성하지 않는다.
- `AIPreview`에는 입력·생성 시각·엔진 버전·구성안을 보존한다. 실제 인물 매핑은 내부에만 둔다.
- `Offer`와 파트너 `Application`은 운영팀·공급자의 소싱 단계다. 브랜드 응답은 모집 상태·건수·기한으로 제한한다.
- `Lineup`과 항목은 공식 제안의 버전·공개 상태·가격·조건·승인 이력을 보존한다. 브랜드용 필드와 공급가·마진 등 내부 필드를 서버에서 분리한다.
- `Deliverable`은 제출 버전·검수·게시·사용권·성과와 연결한다. 문의·댓글은 관련 항목에 연결하고 내부/브랜드 공개 범위를 분리한다.
- 청구와 파트너 지급은 별도 흐름이다. 브랜드는 자기 청구·입금 상태를 보고, 파트너의 지급액·계좌·정산 정보를 보지 않는다.
- 운영팀 대리 등록과 수동 제안 발송으로도 의뢰를 완료할 수 있어야 한다. AI 결과가 없다는 이유로 캠페인 운영이 멈추지 않아야 한다.

### 화면 시안의 검수 기준

- 홈에서 두 경로를 시작하고, 브리프 입력·프리뷰 선택·경로 확정·완료 화면까지 이동할 수 있다.
- 프리뷰·소싱 상태에서는 인물의 이름·채널이 나타나지 않으며, 공식 제안 예시에서만 선택된 인물이 나타난다.
- 공식 제안의 승인·대안 요청, 제작물의 수정 요청·승인에 각각 대상이 분명한 화면이나 팝업이 있다.
- 목록 필터·탭·문의·문서·계정 편집 버튼에 의미 있는 결과가 있으며 예시의 범위를 넘어 실제 전송으로 오해되지 않는다.
- 성과·금액·인물·캠페인은 예시임을 지속적으로 표시한다. 실제 외부 채널이나 연락처처럼 보이는 가짜 링크를 만들지 않는다.
- 작은 화면에서 주요 행동을 찾을 수 있고, 키보드로 폼·탭·팝업을 사용할 수 있다. 팝업의 닫기·취소와 입력 오류가 명확하다.
- 실제 계정·운영 DB·유다오의 체험 횟수·설정에 영향을 주지 않는다.

### 운영 구현의 검수 기준

- 브랜드·구매자 대행사·공급 파트너·운영자, 승인 전·정지 계정을 구분해 화면과 API를 검증한다.
- 프리뷰 응답·HTML·다운로드에 숨겨진 인물 정보가 포함되지 않는다.
- 미발송 제안·다른 조직·다른 캠페인·내부 메모·공급가를 직접 URL이나 API로 조회할 수 없다.
- 브랜드는 공급자의 신청 원문을 받지 않으며 공식 제안의 버전과 항목에 대해 결정한다.
- 제안 만료·새 버전·중복 승인·동시 수정·자료 보완 상황에서 오래된 조건이 승인되지 않는다.
- 제작물 수정·승인·게시 링크·성과·보고서·문서가 같은 캠페인에 연결된다.
- 예산·통화·VAT 표시·환율 기준·제안 유효기간을 일관되게 처리하고 금액 계산은 코드에서 수행한다.
- 수동 입력 데이터와 자동 집계 데이터를 구분하고 집계 기간·갱신 시각을 표시한다.

## 실제 연결 구현 현황

2026-11-01 코드 반영 기준이다. 배포·브라우저 검증 결과와 실제 운영 캠페인의 수행 실적은 별도로 확인해야 한다. `/brand-preview`는 검토용으로 남기고, 인증된 브랜드 화면은 로그인한 조직의 캠페인과 요청 데이터를 조회한다. 실제 데이터가 없으면 빈 상태를 표시하며 예시 캠페인·인물·견적·성과로 채우지 않는다.

| 화면·경로 | 실제 연결 범위 |
| --- | --- |
| 홈 `/advertiser` | 조직별 캠페인 집계, 진행 중 캠페인, 요청 상태, 맞춤 제안·오픈 캠페인 진입 |
| 캠페인 `/advertiser/campaign` | 실제 캠페인 목록, 제목·요약 검색, 상태 필터, 상세 이동. 진행·검토·수정·완료·취소를 색상과 텍스트로 구분 |
| 새 요청 `/advertiser/campaign/new` | 브리프 → 구성 방향 → 진행 방식·확인. `?route=open`으로 초기 경로 선택, `?draft=<id>`로 초안 이어 쓰기 |
| 상세 `/advertiser/campaign/[id]` | 실제 예산·통화·매체·브리프·일정·접수 상태·관련 요청. 공식 제안 버전·공개 크리에이터·견적·항목 승인·수정 요청. 제작 항목·운영팀 공개본·버전별 검수 승인·수정 요청. 관리자 확인 후 공개된 게시 링크·성과·보고 버전. 문서는 대기 상태 |

데이터 인터페이스는 다음과 같다.

- `GET /api/brand/workspace`: 현재 조직의 계정·권한, 캠페인·요청 목록, 전체 상태 집계와 기능 제공 여부를 반환한다. 목록은 최근 100건이며 추가 데이터 여부를 함께 반환한다.
- `GET /api/brand/campaigns/[id]`: 현재 조직이 소유한 캠페인만 조회한다. 다른 조직의 캠페인은 404이며, 공급사의 원신청·공급가·정산·계약을 브랜드 자료로 반환하지 않는다.
- `POST /api/brand/campaigns`: 새 요청, `saveDraft`, `submitDraft`, `cancel`을 처리한다. 초안은 제목만으로 저장할 수 있고, 접수 때 전체 브리프를 검증한다. 캠페인과 연결된 요청을 같은 트랜잭션에서 생성하며 `clientRequestId`로 재시도 중복을 방지하고 `expectedUpdatedAt`으로 오래된 초안 수정·취소를 차단한다. 직접 취소는 작성·검토 단계에서 운영팀이 아직 연결 의뢰를 처리하지 않은 경우에 한하며, 해당 의뢰와 예정 시각을 함께 종료한다.
- 맞춤 제안은 접수 완료 시각을 기준으로 달력 시간 48시간의 제안 예정 시각을 기록한다. 오픈 캠페인은 별도 모집 마감일을 사용하고 48시간 예정 시각을 만들지 않는다. 이 값은 운영 일정이며 공식 제안 자동 생성·발행의 구현을 의미하지 않는다.
- 운영 승인 뒤 DB의 `RECRUITING`은 맞춤 제안에서 내부 **소싱 중**, 오픈 캠페인에서 **모집 중**을 뜻한다. 맞춤 제안은 미래 희망 게시일로 승인하고 에이전시 목록·지원에서는 제외한다. 오픈 캠페인만 미래 모집 마감일을 검증해 공급사 모집에 노출한다.
- 기존 `/api/workspace/campaign-applications`의 GET·POST는 모두 404로 폐기했다. 브랜드의 원신청 조회·후보 지정·직접 선정·거절을 화면에서 숨기는 데 그치지 않고 서버에서도 막는다. 디렉터리·유사 크리에이터·일반 컬렉션 차단도 유지한다.

공식 제안은 `CampaignProposal`·`ProposalItem`·`ProposalDecision`·`ProposalMutation`으로 공급자 신청과 분리했다. 관리자는 캠페인 상세에서 비공개 초안을 작성·저장하고 공개 미리보기를 확인한 뒤 발행한다. 브랜드는 자기 캠페인의 발행본만 조회하며, 인물·채널·제안가·제작 범위·일정·사용권을 확인하고 대기 항목을 선택해 승인하거나 수정을 요청한다. 모든 항목이 승인되면 캠페인을 `IN_PROGRESS`로 전환하고 연결 의뢰를 해결 상태로 변경한다. 일부 항목의 수정 요청은 나머지 항목을 자동 승인하지 않는다.

발행본은 수정할 수 없으며 새 버전으로 대체한다. 만료·대체된 버전, 취소·완료된 캠페인, 이미 결정된 항목에 새 결정을 저장하지 않는다. 동일 요청 재시도는 중복 기록하지 않으며 변경된 버전에 대한 요청은 충돌로 돌려준다. 공개 응답에는 공급사·원신청·공급가·내부 메모·내부 크리에이터 ID를 넣지 않는다. `officialProposals`는 제공 상태로 전환했다. 실제 게시물 검수·지급·계약은 제안 승인에 따라 자동 실행되지 않는다.

관리 API는 `GET/POST /api/admin/proposals`, 브랜드 결정 API는 `POST /api/brand/proposals`다. `20261102000000_add_official_proposals`는 기존 데이터를 변경하지 않는 추가 테이블 마이그레이션이다. [이환 내부 시연](nte-proposal-demo.md)은 지정된 세 테스트 계정의 DB에 네 가지 상태를 저장하며 기존 계정·비밀번호·조직 권한을 유지한다.

제작·검수는 승인된 공식 제안의 `ProposalItem`에 `ProductionItem`을 연결한다. 에이전시의 제출본 `ProductionSubmission`은 수정할 때마다 새 버전으로 저장하고, 관리자가 검수한 공개 제목·링크·설명만 별도 스냅샷으로 브랜드에 전달한다. 브랜드 승인·수정 요청은 공개된 정확한 버전에 기록하며, 새 수정본은 다시 관리자 검수를 거친다. 내부 메모·공급 파트너·미공개 원문은 브랜드 응답에서 제외한다. `productionReview`는 제공 상태로 전환하며 [이환 제작·검수 시연](nte-production-demo.md)은 지정된 계정의 DB에 단계별 상태를 저장한다.

2026-11-02에는 승인된 콘텐츠의 게시·성과 보고를 `ReportingItem`·`ReportingSubmission`·`ReportingMutation`으로 연결했다. 에이전시가 게시 링크와 지표를 제출하고 운영팀이 별도 공개본을 확인해 발행한다. 브랜드는 공개된 최신본과 이전 공개 버전을 읽으며 비공개 업데이트·내부 메모는 볼 수 없다. 미집계와 0을 구분하고 최신 공개본만 합산하며 도달은 합산하지 않는다. `campaignPerformance`를 제공 상태로 전환하며 [이환 게시·성과 시연](nte-reporting-demo.md)을 DB에 저장한다.

**아직 제공하지 않는 기능:** 실제 DB 기반 익명 구성안·추정 견적·성과 예측, 외부 채널 성과 자동 수집, 브랜드 문서 발행·다운로드다. 요청 단계의 세 가지 카드는 검토할 **구성 방향**을 저장하며 AI 산출물이나 확정 견적을 뜻하지 않는다. `anonymousPreview`, `campaignDocuments`는 계속 `false`다. 콘텐츠 검수 승인과 보고서 공개가 실제 SNS 게시·계약·지급을 실행하지는 않는다.
