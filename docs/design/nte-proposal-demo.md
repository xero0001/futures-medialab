# 이환 공식 제안·승인 시연

2026-11-01 · 내부 시연 데이터

이 시연은 이환(Neverness to Everness)의 헤테로 시티, 도시 탐험, 이상 헌터와 에이본이라는 게임 맥락을 사용한다. 게임 설명은 [이환 공식 사이트](https://nte.perfectworld.com/kr/)와 [공식 출시 FAQ](https://nte.perfectworld.com/kr/article/news/gamebroad/20260426/261934.html)를 참고했다. 캠페인·크리에이터·채널·인원·가격·제안·승인 이력은 가상이며, 게임사와의 실제 계약이나 제휴를 뜻하지 않는다.

## 계정과 역할

| 계정 | 화면 | 시연 역할 |
| --- | --- | --- |
| `admin@admin.com` | [관리자](https://futures-medialab-admin.vercel.app/) | 캠페인 상세에서 제안 초안 작성, 브랜드 공개 미리보기, 발행, 수정본 발행 |
| `brand@brand.com` | [브랜드 캠페인](https://futures-medialab.vercel.app/advertiser/campaign?lang=ko) | 자기 캠페인의 발행된 제안 조회, 항목별 승인·수정 요청, 버전·결정 이력 확인 |
| `agency@agency.com` | [에이전시](https://futures-medialab.vercel.app/agency?lang=ko) | 자기 조직의 시연 캠페인 신청·공급 자료 확인. 브랜드의 공식 제안 승인과 공급자 선정은 별도 업무 |

기존 계정·비밀번호·조직 권한을 유지한다. 세 계정의 정확한 조직을 확인한 뒤 그 조직에만 시연 레코드를 추가한다.

## 네 가지 장면

| 캠페인 | 초기 상태 | 확인할 내용 |
| --- | --- | --- |
| `[시연] 이환 · 헤테로 시티 탐험 제안 준비` | 관리자 초안 | 브랜드 응답에 초안·크리에이터 이름·채널이 없음을 확인한 후 관리자가 발행한다. |
| `[시연] 이환 · 한국 크리에이터 도시 탐험` | 발행·승인 대기 | 브랜드가 제안 버전·가격·일정·권리를 보고 항목을 선택해 승인한다. 모두 승인하면 캠페인이 진행 상태로 전환된다. |
| `[시연] 이환 · 도시의 이상한 순간 숏폼` | 수정 요청 | 관리자가 기존 발행본을 복제해 새 버전을 작성하고 수정 이유와 조건을 반영해 발행한다. 대체된 이전 버전은 다시 승인할 수 없다. |
| `[시연] 이환 · 초보 감정사 가이드` | 승인 완료 | 승인된 항목과 결정 이력을 확인한다. 제작물·조회수·실제 정산은 이 시연에서 만들지 않는다. |

시연용 크리에이터는 `라온 플레이 · 시연`, `모아 게임노트 · 시연`, `하루 시티워크 · 시연`이다. 채널 주소는 실제 인물과 혼동되지 않게 예약된 `example.invalid` 도메인을 사용한다. 실제 채널 방문을 위한 주소가 아니다.

## 공개·승인 원칙

- 초안은 관리자만 조회한다. 브랜드에는 캠페인 조건과 제안 준비 상태만 보인다.
- 공식 발행 시점에 크리에이터와 조건을 버전별 스냅샷으로 고정한다. 이후 변경은 새 버전으로 발행한다.
- 브랜드는 자기 조직 캠페인에서 발행된 제안만 조회한다. 새 초안은 기존 발행본이 있어도 공개되지 않는다.
- 공급사, 내부 크리에이터 ID, 공급가, 내부 메모는 브랜드 응답에서 제외한다.
- 브랜드의 OWNER·ADMIN만 결정할 수 있다. MEMBER는 조회만 가능하다.
- 만료·대체된 버전, 취소·완료 캠페인, 이미 결정된 항목에는 새 결정을 저장하지 않는다.
- 승인과 수정 요청은 제안 버전·항목·행위자·시각에 연결한다. 동시 편집과 중복 제출을 구분한다.
- 제안 승인은 지급이나 공급자 계약을 자동 실행하지 않는다.

## 데이터 범위

고정 네임스페이스는 `fm-demo-nte-v1-*`, 표식은 `requirements.demo=true` 및 `seed=official-proposals-nte-v1`이다. 기존 실데이터를 덮어쓰지 않으며 같은 시드를 재실행해도 진행 중인 시연 상태를 초기화하지 않는다. 임의의 금액·조회수를 실제 운영 성과로 합산하는 정산 레코드는 만들지 않는다.
