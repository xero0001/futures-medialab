# 이환 게시·성과 보고 시연

콘텐츠 승인 이후의 흐름을 실제 DB에 연결한다. 지정된 `brand@brand.com`, `agency@agency.com`, `admin@admin.com`과 기존 제안·제작 시연 10개, 보존을 요청한 QA 데이터는 변경하거나 삭제하지 않는다. 별도의 게시·성과 캠페인 6개를 추가한다.

## 사용 흐름

1. 현재 공식 제안에 속한 콘텐츠가 브랜드 승인을 받으면 게시·성과 작업이 생성된다. 기존 승인 콘텐츠는 관리자가 캠페인 상세에서 보고 작업을 준비한다.
2. 에이전시는 프로젝트의 **게시·성과**에서 게시 제목·링크·게시 시각과 성과를 제출한다. 지표가 아직 없으면 빈 값으로 제출할 수 있다.
3. 관리자는 캠페인 상세의 **게시·성과 보고**에서 원문을 검토한다. 보완 요청 또는 별도로 작성한 공개본의 미리보기·공개 확인을 수행한다.
4. 브랜드는 캠페인 상세의 **성과**에서 공개된 게시 링크·집계 시점·지표·설명과 이전 공개 버전을 조회한다. 별도의 브랜드 승인은 요구하지 않는다.
5. 추가 집계는 새 버전으로 제출한다. 검토 중에는 이전 공개본이 유지되고, 새 원문은 브랜드 응답에 포함되지 않는다.

에이전시 OWNER/ADMIN만 제출할 수 있고 MEMBER는 읽기만 가능하다. 관리자는 활성 플랫폼 조직의 OWNER/ADMIN이어야 한다. 폐쇄된 캠페인·교체된 제안·승인 전 콘텐츠에는 새 보고를 등록할 수 없다. 공개본은 덮어쓰지 않으며 세션·조직·역할·리비전·재시도 키를 확인하고 감사 이력을 저장한다. 이 기능이 SNS에 게시하거나 결제·정산을 실행하지는 않는다.

## 지표의 의미

조회·노출·도달·좋아요·댓글·공유·저장·클릭은 각각 정수 또는 빈 값이다. 빈 값은 미제공·집계 중이고 `0`은 실제 입력한 0이다. 하나라도 수치가 있으면 집계 기준 시각이 필요하다. 게시 시각 이후이며 미래가 아닌 시각만 허용한다.

브랜드 합계에는 제작 항목마다 최신 공개 버전을 한 번만 사용한다. 누적 성과의 이전 버전을 합산하지 않으며, 중복 이용자를 제거할 근거가 없는 도달 수는 합산하지 않는다. 서로 다른 집계 시점을 숨기거나 수동 제출 수치를 자동 수집값으로 표시하지 않는다.

## 추가하는 시연 장면

| 캠페인 | 상태 | 확인할 내용 |
| --- | --- | --- |
| 이환 · 도시 탐험 게시 준비 | 제출 대기 | 승인된 콘텐츠에서 첫 게시·성과 등록 |
| 이환 · 헤테로 시티 첫 성과 | 관리자 검토 | 비공개 제출본과 브랜드 공개본 검토 |
| 이환 · 이상한 순간 집계 보완 | 보완 요청 | 운영팀 피드백에 따라 새 버전 제출 |
| 이환 · 도시의 일상 게시 확인 | 공개 완료 | 게시 링크 공개, 지표는 집계 중 |
| 이환 · 에이본 탐험 성과 보고 | 공개 완료 | v1·v2 비교와 최신 공개 수치 |
| 이환 · 도시 탐험 추가 집계 | 추가 집계 검토 | 브랜드는 v1, 운영팀·에이전시는 비공개 v2 확인 |

게시 링크는 [이환 공식 홈페이지](https://nte.perfectworld.com/kr/)에서 연결된 [공식 PV](https://youtu.be/lLmUGwqap6Y) 참고 링크다. 가상 크리에이터의 실제 게시물로 표시하지 않는다. 시연 보고서의 게시 시각과 성과 수치는 가상이며 실제 영상 통계나 실집행 성과가 아니다. 기존 공식 키 이미지·게임 아이콘을 재사용한다.

## API와 데이터

- `GET/POST /api/agency/reporting`: 담당 콘텐츠의 보고 조회·버전 제출
- `GET/POST /api/admin/reporting`: 승인 콘텐츠 보고 작업 준비·보완 요청·별도 공개본 발행
- `GET /api/brand/reporting?campaignId=…`: 자기 캠페인의 공개 보고서만 조회

`ReportingItem`은 승인된 `ProductionItem`에 1:1로 연결한다. `ReportingSubmission`은 원문과 공개 필드를 분리하고 `ReportingMutation`은 중복 요청을 방지한다. 브랜드 조회는 공개 필드만 선택하며 내부 메모·공급 조직·비공개 증빙·미공개 지표는 제외한다.

마이그레이션 `20261102020000_add_post_reporting`은 상태 enum과 위 테이블 3개를 추가한다. 기존 테이블의 데이터나 제안·콘텐츠 승인 상태를 초기화하지 않는다.

```bash
node --experimental-strip-types apps/platform/scripts/seed-nte-reporting.mjs
node --experimental-strip-types apps/platform/scripts/seed-nte-reporting.mjs --apply
```

기본 실행은 읽기 전용이다. `--apply`는 `fm-demo-nte-reporting-v1-*` 범위와 `requirements.reportingSeed=nte-reporting-v1`을 검사한 뒤 전체 6개를 트랜잭션으로 추가한다. 이미 있으면 후속 시연 진행 상황을 유지한다. 실제 제안 발행·브랜드 승인·제작 검수·보고 검토 도메인 함수를 통해 이력을 구성하며 계정 비밀번호·권한을 변경하지 않는다.
