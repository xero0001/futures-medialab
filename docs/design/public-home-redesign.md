## 수정 배경과 방향

첫 구현은 공개 정보의 범위를 좁히면서 시각적 표현과 서비스 설명까지 지나치게 줄였다. 제목, 세 가지 서비스 문장, 문의만으로는 게임 마케팅 회사의 전문성과 협업 경험을 충분히 전달하기 어렵다. `/backup`에 있던 이미지, 업종의 분위기, 단계별 설명을 회복하고 서비스 설명을 구체화한다.

방향은 **게임 마케팅 브랜드의 인상을 주는 첫 화면 → 서비스별 업무와 산출물 → 협업 방식 → 역할별 가입과 문의**다. 기존의 “데스크톱 약 1.5화면” 제약을 폐기하고 내용에 맞춰 길이를 정한다. 이 문서와 구성 시안은 새 구현 기준이며 현재 배포 화면의 구현 완료를 뜻하지 않는다.

플레이스홀더에는 메일·복사·QR 동작을 연결하지 않는다. 실제 값이 정해지면 해당 기능을 추가한다.

## Montage 적용 범위

| 재사용 | 랜딩을 위한 설계 |
| --- | --- |
| `WorkspaceProvider`, Wanted blue `#0066FF`, Pretendard, 중립색 토큰 | 대형 히어로, 이미지 비중, 비대칭 2열 구성 |
| `Button`, `TextButton`, 언어 선택기, 포커스와 상태 | 서비스별 시각 자료와 읽는 순서 |
| 아이콘·모서리·간격 기준 | 화이트·옅은 블루·짙은 블루 배경 전환 |
| 기존 가입·로그인·승인제·다국어 연결 | 큰 제목의 반응형 크기와 줄바꿈 |

버튼 높이 48px·모서리 12px, 본문 16–18px를 유지한다. 데스크톱 히어로 제목 56–64px, 섹션 제목 36–40px, 모바일 히어로 36–40px를 출발점으로 한다. 의미 없는 배지·통계·같은 카드의 반복으로 밀도를 채우지 않는다.

## 상호작용·모바일·구현

- 헤더와 서비스 개요는 실제 영역으로 이동하고 고정 헤더에 제목이 가리지 않도록 스크롤 여백을 둔다.
- 핵심 설명을 자동 캐러셀이나 호버 안에 숨기지 않는다. 모션은 절제하고 `prefers-reduced-motion`을 존중한다.
- 모바일은 제목·본문·CTA·비주얼 순서로, 상세는 같은 정보 순서로 쌓는다. 주요 터치 영역 44px 이상. 한·영·중의 실제 문장 길이를 검수한다.
- 구매자는 `/register?audience=buyer`, 공급자는 `/register/agency`로 연결한다. 기존 가입·승인 API 변경은 필요하지 않다.
- `app/_components/public-home/`에서 `hero`, `service-overview`, `service-story`, `working-principles`, `workflow`, `audience`, `contact`로 구현한다. 서비스 설명은 공통 구조와 데이터로 묶고 비주얼은 개별화한다.
- 시안의 HTML은 구성 검토용이다. 실제 서비스에서는 설치된 Montage 컴포넌트와 공통 모듈을 사용한다.
- 1440·1024·768·390·320px, 한·영·중, 키보드·앵커·가입 연결을 확인한다. 이미지 크기 명시·최적화·첫 화면 우선 로딩·아래 이미지 지연 로딩을 적용한다.
- `/backup`을 유지하고, 새 화면의 검수가 끝나면 현재 배포 경로를 교체한다.

완료 기준: 첫 화면만으로 게임 마케팅 서비스임을 이해하고, 스크롤하면 맡길 수 있는 일·협업 과정·참여 경로를 구체적으로 알 수 있다. 각 영역의 텍스트·이미지·흐름도가 서로 다른 설명 역할을 가져야 한다.
